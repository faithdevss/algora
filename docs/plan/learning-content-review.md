- **Singly Linked List** · formulas[1] · HIGH — "Insert / Delete at tail O(n)* — *O(1) if a tail pointer is maintained" is wrong for delete: deleting the tail of a singly linked list needs the predecessor node, which still takes an O(n) walk even when a tail pointer exists. → "Insert at tail: O(1) with a tail pointer (O(n) without). - **Segment Tree** · codeBlocks[0] · MED — The comment says "tree sized 2n", but the code uses recursive 1-indexed children (2*node, 2*node+1) over [lo, hi]. That layout needs about 4n slots, so a 2n array can overflow when n is not a power of two. It also contradicts formulas[2], which says "About 2n–4n". → "tree sized 4n (recursive 1-indexed layout); the 2n layout applies only to the iterative bottom-up segment tree."
- **K-D Tree / Quad Tree / Octree** · codeBlocks[0] vs formulas[0] · LOW — formulas[0] claims an O(n log n) build, but `build` re-sorts the points at every level (`points.sortedBy { it[axis] }`), which costs O(n log² n). → Note that this simple build is O(n log² n), and that O(n log n) needs linear-time median selection or pre-sorting by each axis.
- **Graph** · crossLinks[0] · LOW — The only cross-link is "Monte Carlo Tree Search", which is not a graph data-structure topic and looks like a mis-link. → Link to related topics such as graph_variants, bfs, dfs, or dijkstras_algorithm.
- **Bloom Filter** · applications[1] · LOW — "check a Bloom filter before an expensive origin fetch to avoid one-hit-wonders" misstates the technique. CDNs (for example Akamai) use the filter to avoid *caching* objects requested only once: an object is cached only on its second request. The filter does not skip origin fetches. → "Caches record first requests in a Bloom filter and cache an object only on a repeat request, so one-hit-wonders don't pollute the cache."
- **Fenwick Tree (BIT)** · applications[1] · LOW — "Merge-sort-style inversion counting is a few lines with a Fenwick tree" mixes up two different methods. Merge sort is one way to count inversions, and the BIT is an alternative that scans the array and queries counts of greater values already seen. → "Counting inversions: an alternative to merge sort — scan the array and query how many larger values were already inserted, O(n log n)."

- **Heap Scheduling** · formulas[2] · HIGH — Task scheduler: "idle slots = (maxCount - 1) · (cooldown + 1)" is wrong. - **DDPG** · steps[4] / codeBlocks[1] comment · MED — "the critic must be frozen for this step" / "Freeze the critic here, or its weights get dragged toward inflating Q" is misleading. - **Actor-Critic** · codeBlocks[0] · MED — `critic_loss = (r + gamma * critic(s2) - critic(s)).pow(2)` lets gradients flow through the bootstrap target V(s′), which is the residual-gradient method, not the TD regression that formulas[2]/steps[4] describe.
